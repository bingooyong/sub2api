# Codex forwarding metadata and tool correlation

## 1. Scope / Trigger

Read this contract when changing Codex-protocol forwarding headers, WebSocket
connection reuse, or native Responses tool history. Headers used by the incoming
client and identities generated by gateway probes are separate inputs.

## 2. Signatures

- `(*OpenAIGatewayService).preserveCodexClientIdentityHeaders(c *gin.Context, account *Account, headers http.Header)`
- `normalizeOpenAIWSHandshakeCompatibility(account *Account, headers http.Header) openAIWSHandshakeCompatibilityKey`
- `codexOAuthTransformOptions.PreserveToolCallIDs bool`
- `codexInputFilterOptions.PreserveCallIDs bool`

These are service-layer contracts. No database schema or public response schema
changes are required.

## 3. Contracts

`gateway.disable_codex_identity_enforcement: true` preserves supplied valid
`User-Agent`, `originator`, and `version` values on forwarding paths for accounts
using `UsesOpenAICodexProtocol()`. Unknown names and independently declared versions
are valid metadata. Missing fields remain absent; the HTTP library may supply its
own default UA. Explicit account UA and `force_codex_cli` retain precedence.

Restore caller metadata after the legacy enforcer and before applicable account
header overrides. Check outer forwarding functions as well as builders: Messages
can add identity headers after its inner builder returns. Include both alpha-search
builders, compact, passthrough, and WebSocket handshakes. Without an incoming request,
do not clear generated headers. Ordinary API-key forwarding and synthetic probe,
authentication, and Live identities retain their existing behavior.

`applyOpenCodeUpstreamUserAgent` is not an account header override. It runs after
identity preservation and replaces `User-Agent` only for an official Command Code
host or an OpenCode account or host. Every other request returns immediately.
Do not move preservation after that helper, and do not remove the helper to keep
the Codex opt-out. The Command Code canonical UA is a Cloudflare 1010 guard.

A WebSocket retains its handshake metadata. With enforcement disabled, its reuse
key must include all effective values of the three identity headers, with
unambiguous boundaries and distinct missing/empty representations.

Native Responses call IDs are opaque correlation values. Set
`PreserveToolCallIDs: true`; preserve distinct IDs up to 64 bytes and use the existing
deterministic compression for longer values. Apply the same rule to outputs and
legacy cross-turn references. Item IDs remain subject to their own validation and
reference rules. Keep account/API-key isolation and stable hash domains intact.

## 4. Validation & Error Matrix

| Condition | Result |
| --- | --- |
| Opt-out, valid caller metadata | Preserve complete values without version elevation |
| OpenCode account/host, or official Command Code host | `applyOpenCodeUpstreamUserAgent` may replace `User-Agent` after preservation |
| Any other account | That helper no-ops; preserved Codex identity remains |
| Opt-out, missing metadata | Do not synthesize Codex metadata |
| Opt-out, invalid HTTP field value | Drop that value; do not trim control bytes into a valid identity |
| No incoming request, API-key account, or explicit UA/Force override | Keep that path's established policy |
| Different effective handshake metadata | Do not reuse the earlier socket |
| Valid native call ID of at most 64 bytes | Keep its value and call/output relationship |
| Oversized native call ID | Bound deterministically, consistently for call and output |
| Invalid item ID | Apply item-ID validation independently of the valid call ID |

## 5. Good / Base / Bad Cases

- Good: `codex_exec` UA/originator with no `version` stays that way when opted out.
- Base: the zero-value config retains legacy identity enforcement.
- Bad: converting `call_abc` and `fc_abc` into one `fc_abc` merges unrelated calls.
- Bad: updating a queued request's header map while reusing a socket whose handshake
  declared another client's metadata does not update the upstream handshake.

## 6. Tests Required

- Exercise real outbound builders with complete, missing, old-version, unknown,
  malformed, and repeated metadata. Cover account UA and Force precedence, API-key
  parity, and synthetic requests lacking a Gin request.
- Test connection acquisition, not just key construction, when changing socket
  compatibility. Distinguish later header values and missing versus empty values.
- Record the body sent by `Forward` to prove distinct call/output pairing, reverse
  output order, native custom/search tools, 64/65-byte boundaries, and stable replay.
- Verify item-reference precedence and invalid-item filtering independently of
  call-ID preservation. Retain preservation-disabled legacy transform tests.
- Tests changing process-wide identity settings remain serial and restore prior
  values with `t.Cleanup`.
- Run backend unit/integration checks and the CI-pinned golangci-lint version; record
  an unavailable environment or pre-existing failure precisely rather than claiming
  that unexecuted checks passed.

## 7. Wrong vs Correct

Wrong: infer a new call ID from its prefix or apply global identity changes to fix
one forwarding path.

```go
// This legacy normalization is unsuitable for native opaque IDs.
normalized := normalizeCodexCallID(callID)
```

Correct: opt native Responses into the existing preservation contract and restore
metadata at final forwarding boundaries, leaving synthetic consumers separate.

```go
opts := codexOAuthTransformOptions{PreserveToolCallIDs: true}
```

Evidence about a release label is not evidence about its wire formatting. For
example, Codex 0.153.4's `os_info` dependency formats Ubuntu `22.04` as `22.4.0`.
See the [audit and sanitized observation](../../../docs/audits/codex-request-compatibility.md)
for exact source references and capture limitations.

## 8. Gateway-generated marker policy

Gateway-generated compatibility instructions must not identify the gateway by
brand in upstream-visible text or tool names. Current markers are
`<codex-image-generation-bridge>`, `<codex-spark-image-unsupported>`, and
`<claude-code-todo-guard>`; the reserved Python alias is `python__codex`.
Legacy `<sub2api-...>` markers are no longer recognized or emitted for new
sessions. Existing `sub2api:` hash namespaces are
internal derivation inputs and must remain stable.

Native WebSocket ingress stages a fingerprint snapshot once per session and
applies it to each turn's `client_metadata`; handshake compatibility must use the
same effective identity values. This keeps HTTP and WebSocket convergence
semantics aligned without changing account/API-key isolation.


For native WS, apply convergence after account scoping in both pooled ingress and
v2 passthrough, including the first frame and later `response.create` / `session.update`
frames. Copy the staged IDs per frame and clear only original-body-session capture
bookkeeping. The handshake identity stays fixed; the default prompt-cache key must
be matched against that frame's pre-convergence session. Never reuse first-frame
body bookkeeping for later turns, or change HTTP snapshot semantics as a shortcut.
Test actual adapter writes with changing body sessions and explicit custom cache
keys; preserve the ordinary API-key guard and account-failover checks.
